# TicoRAW 第二阶段：任务执行、熵编码线索与 16-bit 输出

日期：2026-10-12。承接 [第一阶段](2026-10-12-nikon-ticoraw-phase1.md)。全部 ACR 查询使用已有 `ghidra-project`，没有通过 REA 导入、重新全量分析、执行 Adobe 私有函数或修改工程标注。研究范围仍是 Nikon RAW 压缩解码。

## 本轮结论

1. 从调度器追到真正 worker 入口，并用汇编确认任务函数的 `BLR` 间接执行点；不再只依赖任务表里的函数地址。
2. 恢复两类任务：压缩码流处理与整数重建/输出；找到输出缓冲区回调和另一个可选完成回调，严格区分直接调用、间接调用和传递函数地址。
3. 确认重建代码具有 32-bit 中间整数读取、邻域整数运算、可选 LUT、移位/限幅和 16-bit 输出。这里的 RAW 重建不是颜色渲染。
4. 识别出一个 unary（一元码）helper；实现独立、带边界检查的研究位读取器并通过合成实验。未把它当作完整 TicoRAW 熵解码器。
5. 实图的主 RAW 数据 +`0x95` 发现与 scanner 匹配的 `ff20 0004 0000` 块前缀。该处目前是候选边界，不代表已经验证全部块长或读出系数。

仍未成功解码 `LCR_3520.NEF` 的 CFA；本轮没有接入 Imprint 生产代码。

## 任务与 worker：已证实静态链

初始化链：`FUN_013b5ba0 → FUN_01502024 → FUN_014d54f0`。最后一个函数创建 worker pool，并把 `FUN_014d58b0` 的地址交给 `FUN_014d636c`。线程构造内部尚未展开，但 worker 主循环本身已检查。

提交链：`FUN_013b667c → FUN_01502bb8 → FUN_014d5df4 → FUN_014d6080`。

`FUN_01502bb8` 构造 0x30-byte 任务参数记录，写入函数指针、userdata、行区间和任务依赖。`FUN_014d5df4` 将函数指针与 userdata 复制到 pool 任务记录；`FUN_014d6080` 通知条件变量，并不直接调用 codec。

worker `FUN_014d58b0` 只选择未占用且依赖计数满足条件的任务，解锁后执行任务；汇编位置 **`014d5b0c: blr x9`**。前面的 `ldp x9,x2,[x8]` 同时取得任务函数和 userdata；参数含 worker 编号、slot 编号、userdata。任务成功后更新完成状态并减少依赖计数。

## 码流分块与压缩数据处理

`FUN_01502bb8` 还准备了 `FUN_013ceb54` 的任务地址。该函数读取码流，验证周期性 `ff20`、长度值 4 与块编号，读取后续 24-bit 长度字段，并结合 context +`0x94` 的值计算下一块位置；它将块内数据指针与长度存入任务参数，再调用 `FUN_014d614c` 减少依赖计数、唤醒等待任务。

函数名或数据指针赋值不等于 decoder 已消费块数据。这里由 scanner → 依赖解除 → worker 执行组成调度链，尚未对样本走完这条链。

对样本主 strip 开头 1024 bytes 的只读扫描结果：

| strip 相对偏移 | 候选 marker | 后续 bytes |
|---|---|---|
| `0x0` | `ff10` | 码流开头 |
| `0x2` | `ff50` | `0022` 与 `CONTACT_INTOPIX_` |
| `0x26` | `ff12` | 既有头部 |
| `0x4f` | `ff13` | `000e...` |
| `0x5f` | `ff14` | `0034...` |
| `0x95` | `ff20` | `0004 0000 003b2b 030f...` |

`ff20` 候选位于文件绝对偏移 2,477,717。其长度 4 和编号 0 与 scanner 预期相符；后续 24-bit 数 `0x003b2b=15147`，但尚未确认 context +`0x94` 和 packet-length 含义，不能直接把 15147 当作已证实的完整块长度。这里只记录字节出现及局部布局对应，未扫描整个 15MB 数据段以猜测 marker 边界。

### 基础解码任务：`FUN_013e0b84`

入口从任务参数取 compressed pointer/size，初始化 MSB-first 位缓冲，按 context 控制的行/块和分量循环。已分析到的局部行为包括：读取 `ff20` 并核对编号、读取 packet 长度/控制 bytes、建立多个位流状态、校验消费位数是否与声明区间对应。

两个真实调用点 **`013e1bc8`** 与 **`013e2414`** 进入 `FUN_013e3d84`；后者处理分组控制数据并调用 unary helper。随后 `FUN_013e2a2c`、`FUN_013e2cd8` 和若干函数表参与整数缓冲区处理；输出通过 `FUN_013e2eb8` 或独立重建任务完成。这些 helper 的全部数学含义尚未恢复，暂不将它们确认为具体小波、lifting 或逆量化标准实现。

### Unary：`FUN_013e5828`

本次同时检查伪代码与从 `013e5828` 开始的汇编。顶部 bit 63、62、61 分支直接给出：

| 码字 | 返回值 | 消费位数 |
|---|---:|---:|
| `0` | 0 | 1 |
| `10` | 1 | 2 |
| `110` | 2 | 3 |
| `1110` | 3 | 4 |

其后扫描连续 1 至第一个 0；读取方向为 MSB-first。补充位流时从内存读 32-bit word，用 `REV` 转为 big-endian 顺序。`FUN_013e3d84` 的真实调用包括 `013e5324`、`013e5338` 至 `013e5398` 等。

在已查看的分组路径中，控制位为某值时一组八项被置为同一个预测值；另一分支逐项读取 unary 值并加到基值后写入 byte buffer。这支持该 unary 用于组控制/指数等辅助信息的推测；**不证明它直接编码所有像素残差**，也不能仅据此宣布整个 codec 使用一种简单 unary 编码。

特别限制：原 helper 依赖有效 reservoir 状态，部分补充路径在越界时给零；全为 1 的 reservoir、长 run、损坏流和 padding 的真实语义尚未验证。研究实现的严格截断拒绝与 `max_run=63` 是自主保护措施，不能归因于 ACR 或宣称 ABI/行为完全一致。

## RAW 重建与输出回调

`FUN_0157e824` 读取 `08197950` 的函数指针，汇编 **`0157e940: blr x23`**。初始 thunk `FUN_013c951c` 进入 `FUN_013c8bc8`。

任务参数里的输出回调来自上阶段 `FUN_013b6938` 传入的 `FUN_013b5b44`；在传递处 xref 为 **`PARAM`**，不是直接调用。经过任务记录与重建任务参数，重建函数的 `param_6` 获取输出缓冲区；已确认调用点 **`013c8de0: blr x8`**。此处仍是基于静态参数流关联，没有相机样本运行记录。

`param_7` 是另一可选完成回调，调用点 **`013c8d24: blr x8`**；不能把它与分配/获取输出缓冲区的回调混同。本次没有证明它在 Nikon wrapper 路径为非零。

### 已证实的数值处理

`FUN_013c8bc8` 的 scalar 尾部读取多个 32-bit 整数平面。部分输出计算包含四项邻域和的算术右移 2，再加另一项及偏置；另一些输出直接使用相应平面值加偏置。边界行和末个样本有独立处理，不能只复制内部公式。

随后按条件执行：可选 LUT 查表 → 加舍入偏置 → 算术移位 → 截到非负及上界 → `short` 写入。每两个样本前进 4 bytes；另一个行指针对应第二行。向量路径也存在，但尚未与 scalar 数值逐点核对。

由此可将第一阶段“16-bit 输出候选”收紧为：**本条重建分支确实写入 16-bit 输出样本**。32-bit 中间缓冲与输出分支不是同一格式。仍未确认样本的分支、全部 CFA 相位、边距、数值上界、LUT 是否启用或数值保真，不能据此声称产生了 RGGB 真值。
